# Memory-compile schema — the compile spec (v1)

Single source of truth for the memory-compile task. The compile prompt
(MEMORY_COMPILE_TASK in agent/main.py) sources this file and follows it
exactly. Versioned with the compile task in this repo, reviewed in the same
PR. This asset governs *derived* pages under `/data/memory/knowledge/`; it
does not live there (that is derived data and would risk being clobbered).

## Purpose

Distill the accumulated `/data/logs/*.md` into durable, interlinked, typed
markdown pages a cold cycle can read from one fixed path, without re-deriving
knowledge from the logs each time. Pages are a **cache of ground truth**, never
a replacement for it. The canonical `/data` files (logs, decisions.md, actions/,
ROADMAP.md, INBOX.md, VISION.md) always win on disagreement.

## Layout

One directory, an `index.md` route + three typed subdirectories, all under
`/data/memory/knowledge/` (LLM-Wiki shape):

- `index.md` — the route/catalog. One line per page: `slug — one-line summary
  (Sources YYYY-MM-DD)`. Mechanically regenerated by the compile pass. Fans out
  into the typed pages; `state.md`'s protected "durable knowledge" link points
  here (see Link structure).
- `concepts/<slug>.md` — durable lessons, patterns, failure modes. "What I
  know, and the evidence."
- `system/<slug>.md` — how the runtime actually behaves (model timing, git
  auth, no-checkpointer). "How this environment works, so I don't re-learn it
  cold."
- `built/<slug>.md` — what exists and where (initiatives, commits, PRs).
  Mechanical registry; may be more complete than concepts.

Compile-state marker: `/data/memory/knowledge/.last-compiled` — one line, the
date compiled through (e.g. `2026-09-03`). Only logs newer than the marker are
read. Absent marker = first pass = read all logs.

## Naming

- kebab-case slugs, one concept per page, semantic names.
- No dates in filenames (dates churn; the underlying logs carry them).

## Page shape

Each page <1 KB, always:

```
# <title>
One-line summary.
- Fact / link / evidence — canonical file it indexes (path).
- (3-8 bullets, each pointing at a real file)
Sources: <date> compile pass from /data/logs/<date>.md (link).
```

Plus an optional last section:

```
Related: <other page slug>, <other page slug>
```

## May not contain

- Free-floating claims without a canonical-file pointer (dropped next compile).
- Opinions about people; claims about anyone else.
- Restated log prose.
- Anything already indexed elsewhere (pages point, never restate).

## Coverage policy (distillation = retrieval, decision #5)

Distill only what a cold cycle would otherwise re-derive; everything else stays
in the logs. Absence of a page is a designed answer (grep the logs), not a
failure.

- **SELECT** — test: "would this take >1 read to reconstruct from logs alone?"
  If no, grep handles it. Distill: runtime facts that don't change (system/),
  durable patterns/failure modes (concepts/), registry of what exists (built/,
  more complete).
- **AVOID** — anything the logs answer in one grep; anything state.md already
  indexes; volatile status (PR state, today's task); opinions/speculation/bare
  claims (no canonical-file pointer); restated prose; anything decisions.md /
  actions / ROADMAP already hold.
- **HEALTH** —
  1. Traceability is the invariant: every bullet carries a canonical-file
     pointer; bare claims dropped next compile.
  2. Regenerability: a page is short enough a cold cycle could rebuild it from
     cited logs in one pass; longer than its sources = drift.
  3. Canonical wins: pages are derived, never authoritative.
  4. Staleness marker: the Sources line carries the compile date; an untouched
     page whose cited files changed gets flagged/merged.
  5. Update-in-place over create (only when new evidence adds).
  6. Conservatism bias: unsure = don't create; the log preserves it for a
     future promote.
  7. Cheap audit: small traced pages make drift diff-able in one cycle.

## Link structure (web-of-pages)

- Route: `state.md` (auto-injected every call) carries a protected link to
  `knowledge/index.md` — invariant of current state, never dropped by the
  cycle-end refresh. Retrieval = state → index → page. Max two hops, no global
  search.
- `index.md` fans out into the typed pages.
- **Web-of-pages (amended 2026-09-04):** compile is not just
  write-the-directly-evidenced-page. After writing/updating a page, grep the
  other typed pages for overlapping slugs/terms and add or update the mutual
  links — cross-reference **both directions** ("Related:" sections). Pages
  link to each other where related and cite the canonical files they index.
- Write-back is OUT OF SCOPE in this build: retrieval is strictly read-on-demand.
  Revisit write-back only after the first few compiles prove out.

## Compile mechanics

The compile is a bounded *prompt*, not new machinery. Sequence:

1. Read `/data/sudarshana/agent/schema.md` (this file) and follow it exactly;
   if missing, record that and stop — do not invent rules.
2. Read the marker `/data/memory/knowledge/.last-compiled`. Only logs newer
   than it (a week ≈ 150–250 lines, 1–2 reads).
3. Read the existing knowledge pages to know update-vs-create.
4. Distill per coverage policy: update only when evidence adds; else draft a
   new <1 KB page.
5. Write/update the directly-evidenced page.
6. Refresh related pages: grep the tree for overlapping slugs/terms, update
   mutual "Related:" links both directions (web-of-pages).
7. Regenerate `index.md` mechanically (one line per page: slug — summary —
   Sources date).
8. Bump the marker to the newest log date compiled.
9. Append a line to today's `/data/logs/<date>.md` recording the pass (pages
   created/updated, logs covered, anything flagged).

Compile writes knowledge pages + index.md + marker + a log line **only**. It
does NOT touch state.md (the regular cycle-end refresh owns state.md and keeps
the protected link).

## Cadence

- Weekly, Monday 00:00 America/Los_Angeles — rides the PR #8 weekly freshness
  cron (one trigger serves both once wired).
- First run manual on the 09-01 → 09-03 logs to validate shape (before wiring
  the cron), per the approved plan.
- Incremental, bounded: only logs since the last compile, never the whole
  history.

## Retrieval

- On-demand fixed-path reads, not search: read index.md (tiny TOC) → grep
  knowledge/ for a slug → read the page. Deterministic; zero model calls on
  the lookup.
- What a retrieval returns: the lesson + evidence bullets pointing at
  canonical files + a Sources line (compile date) — the fact, its age, and its
  audit trail in one shot.
- Designed-in fallback: topics not distilled (per AVOID) are deliberately
  absent — that absence is an answer, then grep the logs. Pages are a cache,
  never a replacement.

## Honest cost line

Retrieval is the cheap half (grep = free, one short read); compile (weekly,
bounded) is the pricey half. This is exactly why fixed-path beats RAG: RAG
spends a query-time model call every cold cycle on every possibly-relevant
topic; this spends a fixed-path read only when the route points there. This is
a retrieval/consistency win, not a cost win — it adds a periodic compile run +
write cost, bounded three ways (incremental, low-frequency, small pages).
